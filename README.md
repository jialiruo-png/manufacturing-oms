# Manufacturing OMS — 中小型制造业AI订单管理系统
> 面向中小型机电 / 装备制造企业的**AI订单管理系统**，覆盖从客户接单、审批、采购备料、生产排程、物流发货到老板决策看板的完整业务链条，内含CRM页面，及时跟进客户信息，物料仓库；嵌入多个AI功能，如AI解析订单Excel/订单图片，AI智能识别产品物料，作BOM解析。

## 一、这个系统解决的是什么问题

引入数字化系统前，中小机电厂常见 6 个管理痛点：

1. **订单录入依赖 Excel**：业务员手工填表，版本混乱、易出错，客户信息散落在每位员工的电脑里
2. **采购与生产脱节**：业务员靠微信群通知采购，"漏单 / 错单 / 规格写错"反复发生
3. **库存不透明**：缺货才发现，多采购导致呆滞
4. **审批靠截图**：老板审批通过微信 @，无凭证、责任不清
5. **数据滞后**：月底手工汇总 Excel，经营数据滞后 30 天
6. **客户资产流失**：业务员离职带走客户名单，公司无积累

本系统把上述每个环节都**数字化、可视化、可追溯**，并按 RBAC 控制每个岗位的可见范围。

## 二、目标用户

最适合：

- **年订单量 3,000–50,000 的中小制造企业**（机电 / 装备 / 五金 / 出口外贸均可）
- 业务流程是「接单 → 审批 → 采购备料 → 生产 → 发货」的标准制造流水
- 信息化基础薄弱、目前主要靠 Excel + 微信群驱动
- 希望沉淀客户资产、规范审批、缩短管理半径的老板

不适合：

- 流程化工 / 离散制造大厂（业务复杂度需 ERP 而非 OMS）
- 纯电商 / 零售订单管理（场景模型不一样）

## 三、系统用户与角色（RBAC）

共 **6 类业务角色 + 3 类经理子角色**：

| 角色 | 关键权限 |
|---|---|
| **业务员** sales | 新建订单 / Excel 导入 / 客户档案 / 沟通记录 / 仅看本人订单 |
| **采购** purchasing | 接收已审批订单 / 录入物料清单 / 库存台账 / 备料完成流转 |
| **生产** production | 接收备料完成的生产任务 / 录入生产备注 / 完工流转 |
| **物流** logistics | 待发货列表 / 录入快递单号 / 提交发货审批 |
| **内勤跟单** clerk (manager) | 审批发货 / 全量只读浏览 |
| **审批经理** approval_manager (manager) | 审批订单 / 通过 / 退回修改 / 驳回 |
| **系统管理员** system_admin (manager) | 用户管理 / 注册审核 / 角色分配 / 全量查看 / 改密 |

每次状态变化自动落审计日志，全流程可追溯。

## 四、核心功能模块

> 完整功能清单共 106 个功能点（100 已实现 + 6 预留扩展）。

### 4.1 订单管理
- 全生命周期：**草稿 → 待审批 → 采购中 → 生产中 → 待发货 → 待发货审批 → 已发货**
- 合同编号自动生成 / 侧滑抽屉详情 / 工作流时间线 / 批量筛选

### 4.2 客户管理
- 客户档案（基础信息 + 联系方式 + 地址 + 备注）
- 客户详情页 3 卡片 + 时间线（基本信息 / 沟通记录 / 订单历史）
- 沟通记录全留痕，业务员离职无损交接

### 4.3 采购与物料
- 按订单聚合的物料视图（自主创新点）
- Switch 一键切换备齐状态 / 库存状态标记（正常 / 偏低）

### 4.4 生产计划
- 生产任务列表（按订单维度）/ 备注录入 / 一键完工流转

### 4.5 物流发货
- 待发货 / 已发货分离 / 快递单号录入 / 发货审批留痕

### 4.6 审批工作流（自主创新点）
- 基于**状态机的多角色多级审批**
- 11 个订单状态 + 20+ 条迁移规则
- 支持「退回修改」「驳回发货」等反向流转
- 每次状态变化自动落审计日志

### 4.7 仪表盘与报表
- KPI 卡片（订单数 / 销售额 / 客户数 / 待审批数）
- 月度销售趋势（含同比环比）
- 风险预警订单（临近交期 / 已逾期红标）
- 客户地理分布图（Leaflet 矢量地图）

### 4.8 Excel 智能导入（自主创新点）
- **客户名称智能识别 + 乱码兜底**：五层正则识别 + UTF-8/Latin-1 mojibake 自动检测
- 表头自动识别（35 行内扫描、中英文兼容）
- 日期、金额、装箱信息全自动解析
- 解析预览 → 前端编辑 → 确认导入

### 4.9 用户与权限
- 注册审核机制（自助注册 → 管理员审批）
- **三级权限模型**：路由级 / 接口级 / 数据级
- PBKDF2-SHA512 密码加密 / JWT + tokenVersion 失效控制
- 全部敏感操作落审计日志

## 六、快速开始（本地开发）

### 6.1 前置要求

- Node.js ≥ 20
- PostgreSQL（本地或远程实例）

### 6.2 启动

```bash
# 安装依赖
npm --prefix backend install
npm --prefix frontend install

# 配置后端 .env（参考 .env.example）
cp .env.example backend/.env
# 编辑 backend/.env：填入 DATABASE_URL / JWT_SECRET / DEFAULT_ADMIN_*

# 初始化数据库 schema 与示例数据
npm --prefix backend run db:deploy
npm --prefix backend run db:seed

# 一键启动（同时拉起前后端）
./start.sh
```

- 后端：`http://127.0.0.1:3001`
- 前端：`http://localhost:5173`

### 6.3 生产部署

详见 [`deploy/aliyun/README.md`](deploy/aliyun/README.md) — 完整的阿里云 ECS + RDS + Nginx + PM2 部署流程。

## 九、开发者协作

如果你用 Claude Code / Codex 协作开发，[`AGENTS.md`](AGENTS.md) 给出了仓库的目录约定、命令清单、Schema 变更流程。

主要命令：

```bash
# 本地一键启动
./start.sh

# 后端
cd backend
npm run dev          # 开发模式
npm run build        # 构建
npm run db:deploy    # 应用已有迁移
npm run db:migrate   # 生成新迁移
npm run db:studio    # 打开 Prisma Studio

# 前端
cd frontend
npm run dev          # Vite 开发服务器
npm run build        # 生产构建
```

> **不要** 对生产数据库使用 `db push`，统一走 `db:migrate` → `db:deploy`。

## 十、关于本仓库

本仓库是一个**已交付商业项目的脱敏开源版本**：

- 原项目为某中小机电企业按需开发并交付上线

作为：
- 中小制造业数字化的**参考实现 / 模板**
- 个人作品集 / 开源贡献
- 后续二期开发或其他企业落地的**起点代码**
