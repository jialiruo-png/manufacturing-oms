# B3 部署运维手册

> 适用项目：客户企业制造业订单管理系统（Manufacturing OMS v5）  
> 适用对象：甲方管理人员、企业信息化负责人、服务器运维人员、后续接手开发人员  
> 推荐生产环境：阿里云 ECS + Nginx + PM2 + 阿里云 RDS PostgreSQL  
> 文档目标：甲方可按本文档将系统迁移到自己的服务器和数据库，并完成日常运维、备份和故障排查。

## 一、总体说明

本系统采用前后端分离架构。前端构建为静态文件，由 Nginx 对外提供访问；后端为 Node.js / Express API，由 PM2 守护运行；数据库使用阿里云 RDS PostgreSQL，后端通过 RDS 内网地址连接数据库。

第一阶段交付推荐使用云上成熟架构：

```text
用户浏览器
   |
   | HTTP / HTTPS
   v
阿里云 ECS / Nginx :80/:443
   |-- 前端静态文件：/var/www/manufacturing-oms-v5/frontend/dist
   |
   |-- /api/* 反向代理
          |
          v
      Express API / PM2
      127.0.0.1:3001
          |
          v
      阿里云 RDS PostgreSQL
      内网地址 + 白名单放行 ECS 私网 IP
```

系统主要组件：

| 层级 | 技术 | 部署位置 | 说明 |
|---|---|---|---|
| 前端 | React 18 + Vite | ECS `frontend/dist` | 浏览器访问的业务界面 |
| 后端 | Express + TypeScript | ECS PM2 | 提供 `/api/*` 接口 |
| 数据库 | PostgreSQL | 阿里云 RDS | 保存订单、客户、物料、库存、用户等业务数据 |
| 反向代理 | Nginx | ECS | 访问入口、静态资源、API 代理 |
| AI 辅助 | 阿里云 DashScope | 云服务 API | Excel AI 解析、订单图片识别、采购物料建议 |

## 二、企业迁移前准备

企业准备自己的运行环境时，需要先确认以下信息。

### 2.1 服务器与数据库

| 项目 | 建议配置 |
|---|---|
| ECS 地域 | 与 RDS 同地域 |
| ECS 网络 | 与 RDS 同 VPC |
| ECS CPU | 2 核及以上 |
| ECS 内存 | 2 GB 及以上，试运行可 1 GB 起步 |
| ECS 系统盘 | 40 GB 及以上 |
| 带宽 | 3 Mbps 及以上 |
| 操作系统 | Ubuntu 22.04 LTS / Ubuntu 24.04 LTS / Alibaba Cloud Linux 3 |
| 数据库 | 阿里云 RDS PostgreSQL |
| 数据库端口 | 5432 |
| 数据库名 | 建议 `manufacturing_oms` |
| 数据库账号 | 建议使用业务专用账号，不使用高权限管理账号运行应用 |

### 2.2 网络与安全组

ECS 安全组建议：

- 开放 `22/tcp`：SSH 管理。
- 开放 `80/tcp`：HTTP 访问。
- 开放 `443/tcp`：HTTPS 访问。
- 不开放 `3001/tcp`：后端只监听 `127.0.0.1:3001`，由 Nginx 代理。

RDS 白名单建议：

- 只加入 ECS 私网 IP，例如 `172.xx.xx.xx/32`。
- 不建议开放 `0.0.0.0/0`。
- 后端优先使用 RDS 内网地址，不使用公网地址。

### 2.3 企业需要准备的信息

部署前请整理以下信息：

| 信息 | 示例 |
|---|---|
| ECS 公网 IP | `121.xx.xx.xx` |
| ECS 私网 IP | `172.xx.xx.xx` |
| RDS 内网地址 | `pgm-xxxx.pg.rds.aliyuncs.com` |
| RDS 端口 | `5432` |
| RDS 数据库名 | `manufacturing_oms` |
| RDS 业务账号 | `oms_app_user` |
| RDS 业务账号密码 | 由企业管理员保存 |
| 系统正式域名 | `oms.example.com` |
| 首个管理员手机号或登录名 | 企业指定 |
| DashScope API Key | 可选，用于 AI 功能 |

## 三、ECS 基础环境安装

以下命令以 Ubuntu 系统为例。若企业使用其他 Linux 发行版，可由运维人员按等价方式安装。

### 3.1 登录服务器

```bash
ssh root@企业服务器公网IP
```

登录成功后，终端通常显示类似：

```text
root@iZxxxx:~#
```

### 3.2 安装基础软件

```bash
apt update
apt install -y git curl nginx postgresql-client
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs
npm install -g pm2
```

确认版本：

```bash
node -v
npm -v
pm2 -v
psql --version
nginx -v
```

要求：

- Node.js 显示 `v20.x` 或更高。
- PM2 可以正常输出版本号。
- `psql` 可以正常输出版本号。

### 3.3 创建目录

```bash
mkdir -p /var/www
mkdir -p /var/log/manufacturing-oms
```

推荐项目目录固定为：

```text
/var/www/manufacturing-oms-v5
```

## 五、RDS 数据库准备

### 5.1 创建数据库和账号

在阿里云 RDS 控制台中完成：

1. 创建 PostgreSQL 实例。
2. 创建数据库，例如 `manufacturing_oms`。
3. 创建业务账号，例如 `oms_app_user`。
4. 授权该账号访问 `manufacturing_oms`。
5. 记录 RDS 内网地址和端口。
6. 在 RDS 白名单中加入 ECS 私网 IP。

### 5.2 验证 ECS 到 RDS 连通性

在 ECS 上执行：

```bash
psql "postgresql://RDS账号:RDS密码@RDS内网地址:5432/manufacturing_oms?sslmode=disable" -c "select current_database(), current_user;"
```

成功时会看到类似：

```text
 current_database | current_user
------------------+--------------
 manufacturing_oms | oms_app_user
```

如果连接失败，按顺序检查：

1. RDS 白名单是否包含 ECS 私网 IP。
2. ECS 和 RDS 是否在同一地域、同一 VPC。
3. 数据库名是否创建正确。
4. RDS 账号是否授权该数据库。
5. 密码是否正确。
6. 端口是否为 `5432`。
7. 连接串是否使用 `sslmode=disable`。

### 5.3 RDS 存储加密

企业可在 RDS 控制台开启云盘加密。该能力保护底层磁盘和快照，对应用透明：

- 不影响前端、后端和 Prisma 查询。
- 不影响管理员在系统内查看业务数据。
- 不会自动加密导出的本地 `.dump` 备份文件。

如控制台显示“升降配中”，通常表示 RDS 正在执行加密、配置或规格变更任务。等待实例状态恢复“运行中”后，再进行业务验证。

## 六、后端环境变量配置

### 6.1 创建 `.env`

在 ECS 上执行：

```bash
cd /var/www/manufacturing-oms-v5
cp backend/.env.example backend/.env
chmod 600 backend/.env
nano backend/.env
```

### 6.2 生产环境变量模板

将 `backend/.env` 改成企业真实值：

```bash
NODE_ENV=production
HOST=127.0.0.1
PORT=3001
FRONTEND_ORIGIN="http://企业服务器公网IP,https://企业正式域名"

JWT_SECRET="使用 openssl rand -base64 48 生成"

DATABASE_URL="postgresql://RDS账号:RDS密码@RDS内网地址:5432/manufacturing_oms?sslmode=disable"
DATABASE_URL_UNPOOLED="postgresql://RDS账号:RDS密码@RDS内网地址:5432/manufacturing_oms?sslmode=disable"

DEFAULT_ADMIN_NAME="系统管理员"
DEFAULT_ADMIN_PHONE="企业管理员手机号或登录名"
DEFAULT_ADMIN_PASSWORD="企业交付时设置的临时强密码"
DEFAULT_ADMIN_DEPARTMENT="管理部"

DASHSCOPE_API_KEY=""
DASHSCOPE_MODEL=qwen-turbo
DASHSCOPE_VL_MODEL=qwen-vl-plus
ANTHROPIC_API_KEY=""
```

生成 `JWT_SECRET`：

```bash
openssl rand -base64 48
```

注意：

- `JWT_SECRET` 必须至少 32 位，必须使用强随机值。
- `FRONTEND_ORIGIN` 是允许访问后端 API 的前端地址，多个地址用英文逗号分隔。
- `DATABASE_URL` 和 `DATABASE_URL_UNPOOLED` 在当前 RDS 场景下可相同。
- `DASHSCOPE_API_KEY` 为空时，系统主流程可用，但 AI 功能不可用。
- 真实 `.env` 不得提交到代码仓库。
- 修改 `.env` 后，必须执行 `pm2 restart manufacturing-oms-api --update-env` 才会生效。

### 6.3 首个管理员账号

当数据库没有用户时，后端启动会根据以下变量初始化首个管理员：

```bash
DEFAULT_ADMIN_NAME="系统管理员"
DEFAULT_ADMIN_PHONE="企业管理员手机号或登录名"
DEFAULT_ADMIN_PASSWORD="企业交付时设置的临时强密码"
DEFAULT_ADMIN_DEPARTMENT="管理部"
```

建议流程：

1. 部署前设置一个临时强密码。
2. 首次登录后立即在系统内修改密码。
3. 后续账号通过系统“用户管理”页面创建、审核和停用。

## 七、安装依赖、构建与数据库迁移

### 7.1 安装依赖

```bash
cd /var/www/manufacturing-oms-v5
npm --prefix backend ci
npm --prefix frontend ci
```

### 7.2 构建后端

```bash
npm --prefix backend run build
```

### 7.3 构建前端

推荐使用安全构建脚本：

```bash
npm run build:frontend:safe
```

该脚本会先构建到 `frontend/dist-next`，再安全合并到 `frontend/dist`，避免用户停留在旧页面时因旧 hash chunk 被删除导致白屏。

### 7.4 执行数据库迁移

生产数据库结构由 Prisma migrations 管理，只执行：

```bash
npm --prefix backend run db:deploy
```

禁止在生产数据库执行 `prisma db push`。

迁移文件位于：

```text
backend/prisma/migrations
```

### 7.5 一键顺序参考

```bash
cd /var/www/manufacturing-oms-v5
npm --prefix backend ci
npm --prefix frontend ci
npm --prefix backend run build
npm run build:frontend:safe
npm --prefix backend run db:deploy
```

## 八、数据迁移到企业 RDS

如果企业需要从已有运行环境搬迁到企业自己的 RDS，建议按以下流程操作。

### 8.1 迁移前冻结窗口

迁移当天建议约定一个短暂停用窗口：

1. 通知业务人员暂停新增和修改订单。
2. 确认旧系统无人继续录入。
3. 导出旧数据库备份。
4. 恢复到新 RDS。
5. 新系统验证通过后再开放使用。

### 8.2 导出旧数据库

在能访问旧数据库的机器上执行：

```bash
pg_dump "旧DATABASE_URL" -Fc -f manufacturing_oms.dump
```

其中 `-Fc` 表示 PostgreSQL 自定义格式，适合恢复和校验。

### 8.3 恢复到企业新 RDS

在能访问企业 RDS 的机器上执行：

```bash
pg_restore --clean --if-exists --no-owner --no-privileges \
  -d "postgresql://RDS账号:RDS密码@RDS内网地址:5432/manufacturing_oms?sslmode=disable" \
  manufacturing_oms.dump
```

恢复后执行迁移：

```bash
cd /var/www/manufacturing-oms-v5
npm --prefix backend run db:deploy
```

### 8.4 迁移后校验

建议至少检查：

```bash
psql "postgresql://RDS账号:RDS密码@RDS内网地址:5432/manufacturing_oms?sslmode=disable" -c '\dt'
```

系统页面检查：

- 管理员可以登录。
- 用户列表存在。
- 客户列表存在。
- 产品列表存在。
- 订单列表存在。
- 采购物料和库存页面可打开。
- 数据看板可打开。
- 新建一条测试订单可完整流转。

## 十、Nginx 配置前端和 API 代理

### 10.1 创建配置

```bash
nano /etc/nginx/conf.d/manufacturing-oms.conf
```

参考配置：

```nginx
server {
    listen 80;
    server_name 企业服务器公网IP 企业正式域名;

    root /var/www/manufacturing-oms-v5/frontend/dist;
    index index.html;

    client_max_body_size 20m;

    location /api/ {
        proxy_pass http://127.0.0.1:3001/api/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /assets/ {
        try_files $uri =404;
        access_log off;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    location / {
        try_files $uri $uri/ /index.html;
        add_header Cache-Control "no-cache";
    }
}
```

### 10.2 检查并重载

```bash
nginx -t
systemctl reload nginx
systemctl enable nginx
```

公网验证：

```bash
curl http://企业服务器公网IP/api/health
```

浏览器访问：

```text
http://企业服务器公网IP
```

## 十一、域名与 HTTPS

### 11.1 域名解析

正式上线建议使用企业域名：

1. 准备域名。
2. 完成域名实名。
3. 如使用大陆服务器，按企业情况完成 ICP 备案。
4. 将域名 A 记录解析到 ECS 公网 IP。
5. 将域名加入 `backend/.env` 的 `FRONTEND_ORIGIN`。
6. 重启后端并重载 Nginx。

示例：

```bash
FRONTEND_ORIGIN="https://oms.example.com"
pm2 restart manufacturing-oms-api --update-env
nginx -t
systemctl reload nginx
```

### 11.2 HTTPS

可以使用：

- 阿里云 SSL 证书。
- 企业自有证书。
- Certbot / Let's Encrypt。

启用 HTTPS 后建议：

- HTTP 自动跳转 HTTPS。
- `FRONTEND_ORIGIN` 改为 HTTPS 域名。
- 定期检查证书到期时间。

## 十二、AI 功能配置

AI 功能依赖阿里云 DashScope API Key，包括：

- 销售端 Excel AI 智能解析。
- 销售端订单图片识别。
- 采购端 AI 补全物料建议。

配置方式：

```bash
cd /var/www/manufacturing-oms-v5
nano backend/.env
```

填入：

```bash
DASHSCOPE_API_KEY="企业自己的DashScope API Key"
DASHSCOPE_MODEL=qwen-turbo
DASHSCOPE_VL_MODEL=qwen-vl-plus
```

重启后端：

```bash
pm2 restart manufacturing-oms-api --update-env
```

验证是否配置：

```bash
node -e "require('dotenv').config({path:'backend/.env'}); console.log(process.env.DASHSCOPE_API_KEY ? 'DASHSCOPE_API_KEY 已配置' : 'DASHSCOPE_API_KEY 未配置')"
```

说明：

- AI 只作为录入辅助。
- 订单、物料和采购结果仍以人员确认后的内容为准。
- 不配置 API Key 不影响登录、订单、采购、库存、生产、物流等主流程。

## 十三、备份与恢复

### 13.1 备份策略

推荐“双层备份”：

1. RDS 自动备份。
2. 企业经理或管理员电脑本地冷备份。

RDS 控制台建议：

- 开启自动备份。
- 试运行阶段至少保留 7 天。
- 正式生产可根据企业制度延长。
- 重要迁移、批量导入、上线前后应确认自动备份点可用。

### 13.2 本地冷备份

企业可在经理或管理员电脑保留周期性冷备份。

推荐目录：

```bash
~/Desktop/Database
```

手动备份命令：

```bash
mkdir -p "$HOME/Desktop/Database"
pg_dump "postgresql://RDS账号:RDS密码@RDS地址:5432/manufacturing_oms?sslmode=disable" \
  -Fc \
  -f "$HOME/Desktop/Database/manufacturing_oms_$(date +%Y%m%d_%H%M%S).dump"
```

说明：

- `.dump` 是 PostgreSQL 自定义格式，不是普通 Excel 或文本。
- RDS 存储加密不会自动加密导出的本地备份文件。
- 本地电脑保存真实业务数据时，应启用电脑磁盘加密，或对备份文件单独加密。

### 13.3 恢复演练

建议正式上线后每月至少做一次恢复演练：

1. 新建临时数据库。
2. 恢复最新备份。
3. 修改测试环境 `DATABASE_URL` 指向临时库。
4. 登录系统。
5. 检查订单列表、客户列表、数据看板和 Excel 导入。

恢复命令示例：

```bash
pg_restore --clean --if-exists --no-owner --no-privileges \
  -d "postgresql://RDS账号:RDS密码@RDS地址:5432/临时数据库?sslmode=disable" \
  manufacturing_oms_YYYYMMDD_HHMMSS.dump
```

- 备份任务失败提醒。

## 十六、故障排查

### 16.1 常见错误对照表

| 现象 | 可能原因 | 排查方式 | 处理建议 |
|---|---|---|---|
| 页面打不开 | Nginx 未启动或安全组未开放 80/443 | `systemctl status nginx` | 启动 Nginx，检查安全组 |
| 前端白屏 | 静态资源构建异常或缓存旧资源 | 浏览器控制台、Nginx 日志 | 使用 `npm run build:frontend:safe` 重新构建 |
| API 502 | 后端未启动或端口异常 | `pm2 status`、`curl 127.0.0.1:3001/api/health` | 重启 PM2 |
| 登录失败 | 用户未审核、密码错误、账号停用 | 后端日志、用户管理页面 | 审核账号或重置密码 |
| 数据库连接失败 | `DATABASE_URL` 错误、RDS 白名单未放行 ECS 私网 IP、RDS 状态异常 | PM2 error 日志、`psql` 测试 | 检查 `.env`、白名单、RDS 状态 |
| 迁移失败 | 数据库权限不足或历史数据不符合约束 | `npm --prefix backend run db:deploy` 输出 | 先备份，再处理历史数据 |
| Excel 导入失败 | 文件类型、大小、格式不符合要求 | 前端提示、后端日志 | 使用 `.xlsx/.xls`，控制文件大小 |
| AI 功能不可用 | 未配置 `DASHSCOPE_API_KEY` 或 API Key 无效 | 后端日志、AI 按钮提示 | 配置 Key 并重启 PM2 |
| CORS 错误 | `FRONTEND_ORIGIN` 未配置当前域名 | 浏览器控制台 | 更新 `FRONTEND_ORIGIN` 并重启后端 |

### 16.2 排查顺序

建议按以下顺序排查：

1. 检查 ECS 是否可访问：安全组、公网 IP、Nginx 状态。
2. 检查 Nginx 配置：`nginx -t`。
3. 检查后端健康接口：`curl http://127.0.0.1:3001/api/health`。
4. 检查 PM2 状态：`pm2 status`、`pm2 logs`。
5. 检查数据库连接：用 `psql` 连接 `DATABASE_URL`。
6. 检查 `backend/.env` 是否正确。
7. 检查前端构建产物：`frontend/dist/index.html` 和 `frontend/dist/assets`。
8. 检查浏览器控制台错误。
9. 涉及数据变更时，先备份再处理。

# 进入项目目录

# 重载 Nginx
systemctl reload nginx

# 后端健康检查

psql "postgresql://RDS账号:RDS密码@RDS内网地址:5432/manufacturing_oms?sslmode=disable" -c "select current_database(), current_user;"

## 十九、交付后的管理建议

1. 企业应指定一名系统管理员负责账号审批、权限分配和密码重置。
2. 企业应指定一名运维负责人保存 ECS、RDS、域名、证书和备份相关账号。
3. 真实 `.env` 文件只保存在服务器，不进入代码仓库和交付文档。
4. 每次版本更新前先确认数据库备份。
5. 每月至少做一次备份恢复演练。
6. 业务数据以系统内记录和数据库备份为准，不建议通过人工修改数据库绕过系统流程。
