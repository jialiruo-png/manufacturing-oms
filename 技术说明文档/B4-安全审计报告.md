## 一、报告概述

智能制造订单管理系统是一套面向制造业订单全生命周期管理的企业级业务系统，覆盖客户建档、订单录入、审批流转、采购备料、生产跟进、物流发货、库存台账、经营看板和账号权限管理等核心环节。

本报告面向甲方管理层、系统管理员和验收人员，说明系统在当前交付版本中已经具备的安全能力、数据保护措施、备份恢复方案和运维管理建议。报告重点关注系统正式使用时的安全可靠性、数据可控性和运维可恢复性。

经审计，本系统已建立较完整的基础安全体系：身份认证、角色权限、后端强制授权、数据库访问隔离、数据库存储加密、备份恢复、输入校验、文件上传校验和审计留痕均已纳入系统设计。系统可进入受控生产试运行阶段，并可在后续正式上线中继续叠加 HTTPS、恢复演练和定期安全检查。

## 四、系统安全架构

系统采用“前端访问控制 + 后端强制授权 + 数据库约束 + 云端安全能力 + 本地备份兜底”的多层安全架构。

当前生产架构为：

- 前端：React 静态页面，由 Nginx 对外提供访问。
- 后端：Express + TypeScript 服务，由 PM2 守护运行。
- 数据库：阿里云 RDS PostgreSQL 托管数据库。
- 部署环境：阿里云 ECS 服务器。
- 网络路径：用户访问 ECS，ECS 通过阿里云内网访问 RDS。

该架构的安全优势包括：

1. 后端服务不直接暴露数据库账号和数据库端口。
2. 数据库不作为公网业务入口，主要通过 ECS 内网访问。
3. RDS 白名单限制可访问数据库的来源。
4. Nginx 统一承接外部访问，后端服务由反向代理转发。
5. 数据库由 RDS 托管，具备云端备份、监控、加密和实例管理能力。
6. 企业保留本地冷备份，避免单一云端数据副本风险。

## 五、身份认证安全

### 5.1 登录认证

系统所有核心业务功能均要求用户登录后访问。用户登录成功后由后端签发登录凭证，前端在后续接口请求中携带该凭证，后端统一校验用户身份。

安全效果：

- 未登录用户不能访问订单、客户、库存、审批、用户管理等业务数据。
- 登录身份由后端解析确认，避免前端伪造角色直接操作。
- 登录凭证设置有效期，降低长期登录态泄露风险。

### 5.2 密码保护

系统不保存用户明文密码。用户密码经过不可逆哈希处理后写入数据库。

安全效果：

- 数据库中不存在可直接读取的明文密码。
- 即使数据库备份文件被非授权人员拿到，也无法直接获得用户登录密码。
- 管理员重置密码后，用户旧登录状态会失效。

### 5.3 登录失败保护

系统对连续登录失败具备锁定机制，记录登录失败次数、失败时间和锁定状态。

安全效果：

- 降低密码被暴力猜测的风险。
- 异常登录行为可通过账号状态和日志排查。
- 管理员可对异常账号进行停用、重置密码或权限调整。

## 六、权限控制安全

系统采用基于角色的访问控制模型，并结合经理层细分权限进行业务授权。

### 6.1 主要角色权限

| 角色 | 主要权限边界 |
|---|---|
| 业务员 | 客户维护、订单录入、Excel 辅助导入、本人业务订单跟踪 |
| 采购 | 查看已审批订单、维护采购物料、管理库存台账 |
| 生产 | 查看待生产订单、维护生产状态和生产进度 |
| 物流 | 查看待发货订单、录入物流信息、跟踪发货状态 |
| 经理层 | 按授权范围审批订单、查看经营看板、协助管理业务流程 |
| 管理员 | 管理账号、角色、权限和系统基础配置 |

### 6.2 后端强制授权

系统不仅在前端按角色显示不同页面和按钮，也在后端接口层进行权限判断。

安全效果：

- 普通用户无法通过修改页面请求绕过权限。
- 业务员不能越权操作其他岗位的流程动作。
- 经理层权限可按企业实际分工细分，不简单等同于全权限。
- 用户停用、删除或修改密码后，旧登录态会被拒绝。

### 6.3 业务流程约束

订单按状态流转，系统限制每个角色只能在合适阶段执行对应动作。

典型流程包括：

1. 业务员创建订单草稿并提交审批。
2. 审批通过后进入采购备料。
3. 采购备齐后流转到生产。
4. 生产完成后流转到物流。
5. 物流发货后订单归档或进入后续跟踪。

安全效果：

- 避免跳过审批直接进入生产或发货。
- 避免非授权岗位修改关键业务状态。
- 每次审批和状态变更均保留操作记录。

## 七、数据库安全

### 7.1 数据库部署安全

系统数据库采用阿里云 RDS PostgreSQL 托管服务，数据库名称为 `manufacturing_oms`。业务后端通过阿里云内网地址访问 RDS，不将数据库作为普通公网入口暴露。

安全效果：

- 数据库和应用服务器分离，降低单点故障和误操作影响。
- RDS 白名单限制访问来源，降低数据库被外部扫描或直接攻击的风险。
- 数据库由云服务托管，具备更稳定的备份、监控和实例管理能力。

### 7.2 RDS 存储加密

系统已将数据库静态数据保护纳入阿里云 RDS 云盘加密方案。RDS 云盘加密用于保护云端磁盘、快照和底层存储介质中的数据。

安全价值：

- 云端数据库磁盘数据以加密形式保存。
- 降低底层存储介质、云盘快照或备份介质泄露导致明文数据暴露的风险。
- 加密能力对业务系统透明，不影响业务员、采购、生产、物流和管理层正常使用系统。
- 企业授权用户仍可通过系统正常查看、处理和导出业务数据，确保数据可用性与管理可控性。

需要说明的是，数据库存储加密保护的是云端静态存储介质，不等同于“管理员无法查看业务数据”。企业授权人员仍可依据岗位权限查看其应当查看的数据，这是企业经营系统正常运行的必要条件。

### 7.3 数据库访问权限

数据库连接信息保存在服务器环境变量中，不写入前端页面和交付文档。应用连接数据库时仅连接本项目业务库。

安全建议：

- 数据库账号和密码应由企业负责人或指定管理员保管。
- 不应通过微信、截图、公开文档传播数据库密码。
- 如管理员离职或密码疑似泄露，应及时更换数据库密码和服务器登录凭证。

### 7.4 数据一致性约束

系统通过数据库约束和后端校验共同保护核心业务数据：

- 订单、订单明细、客户、物料、库存、用户等数据之间建立明确关联。
- 库存数量、订单数量、单价、金额等关键字段做合法性校验。
- 订单状态流转由后端控制，避免非法状态写入。
- 用户账号、角色、状态和权限字段由服务端统一维护。

## 八、备份与恢复安全

系统采用“云端自动备份 + 企业本地冷备份”的双层备份策略。

### 8.1 RDS 自动备份

阿里云 RDS 提供数据库自动备份能力，用于云端恢复、误操作回滚和故障恢复。

安全价值：

- 数据库发生异常时，可通过 RDS 控制台恢复到指定备份点。
- 云端备份由 RDS 平台管理，降低人工备份遗漏风险。
- 可配合实例快照和恢复实例进行数据核验。

### 8.2 企业经理电脑本地冷备份

系统已配置定期本地冷备份方案：每 7 天将 RDS 数据库导出为 PostgreSQL 可恢复备份文件，保存到企业经理电脑桌面的 `Database` 文件夹，并生成 SHA256 校验文件。

安全价值：

- 企业负责人掌握独立于云端的数据库副本。
- 云账号异常、误操作、服务迁移或重大故障时，仍保留可恢复数据。
- SHA256 校验文件可用于确认备份文件是否完整、是否被意外损坏。

### 8.3 本地备份文件说明

本地备份文件通常为 `.dump` 格式，不是普通 Excel 或文本文件，不能直接双击阅读，但可通过 PostgreSQL 恢复工具还原为完整数据库。

需要特别说明：

- RDS 云盘加密不会自动加密本地导出的 `.dump` 文件。
- 当前方案优先保证企业负责人可控、可恢复、可交接。
- 如果备份文件需要多人接触、长期外带或同步到第三方网盘，建议再增加独立文件加密或使用加密硬盘。

### 8.4 备份管理建议

为保证备份安全，建议甲方落实以下管理要求：

1. 经理电脑设置强密码和磁盘加密。
2. `Database` 备份目录不得同步到公共网盘或共享聊天工具。
3. 定期检查备份文件生成时间和 SHA256 校验文件。
4. 至少每季度进行一次恢复演练，确认备份可用。
5. 企业关键人员变更时，应同步交接备份目录、服务器账号和数据库账号。

## 九、数据传输与网络安全

### 9.1 ECS 与 RDS 内网通信

系统后端部署在阿里云 ECS，数据库部署在阿里云 RDS。ECS 访问 RDS 时使用同地域内网地址，减少数据库连接暴露面。

安全效果：

- 数据库无需作为公网入口向外暴露。
- 内网通信相比公网连接更稳定、延迟更低。
- RDS 白名单可精确限制允许访问数据库的服务器来源。

### 9.2 Nginx 反向代理

系统通过 Nginx 对外提供统一访问入口，前端静态资源和后端 API 由 Nginx 统一转发。

安全效果：

- 后端业务端口不需要直接暴露给外部用户。
- 便于统一配置访问日志、请求体大小限制、HTTPS 证书和后续安全策略。
- 出现异常访问时，可通过 Nginx 日志进行初步排查。

### 9.3 HTTPS 建议

当前系统已具备启用 HTTPS 的部署条件。正式上线使用企业域名时，建议配置 SSL 证书，并将 HTTP 请求自动跳转到 HTTPS。

HTTPS 的安全价值：

- 保护用户登录凭证。
- 防止订单、客户、库存等业务数据在传输过程中被窃听。
- 提高企业系统对外访问的可信度。

## 十、接口与输入安全

### 10.1 参数校验

系统后端对订单、客户、用户、库存、物料、审批动作和 Excel 导入等关键接口进行参数校验。

安全效果：

- 防止非法 ID、非法状态、负数金额、异常日期等数据进入系统。
- 降低异常输入导致系统报错或数据污染的风险。
- 提高前后端交互的稳定性和可维护性。

### 10.2 SQL 注入防护

系统数据库访问主要通过 Prisma ORM 完成，业务数据查询、创建、更新和删除均采用结构化接口，避免将用户输入直接拼接为 SQL 字符串。

安全效果：

- 降低 SQL 注入风险。
- 提高数据库操作的一致性。
- 便于后续通过数据库迁移维护表结构。

### 10.3 错误处理

系统对常见业务错误返回明确提示，例如未登录、无权限、参数错误、文件格式错误、数据缺失等。

安全效果：

- 减少系统内部错误细节暴露给普通用户。
- 便于用户按提示修正操作。
- 便于管理员根据日志定位问题。

## 十一、Excel 上传安全

系统支持业务员上传订单 Excel 作为录入辅助，但 Excel 上传不直接绕过业务审核和人工确认。

### 11.1 文件类型限制

系统仅允许上传 `.xlsx` 和 `.xls` 类型的订单文件，并对文件扩展名、MIME 类型、文件头签名和解析结果进行校验。

安全效果：

- 防止任意文件伪装成订单附件上传。
- 降低可执行文件、脚本文件或异常大文件进入系统的风险。
- 上传文件在内存中解析，不作为长期临时文件留存在服务器。

### 11.2 文件大小限制

系统对 Excel 上传文件大小进行限制，并由 Nginx 和后端共同控制请求体大小。

安全效果：

- 避免异常大文件占用服务器内存和网络资源。
- 降低恶意上传导致服务不可用的风险。

### 11.3 当前文件一致性校验

Excel 预览和导入流程具备当前文件一致性校验。系统会识别当前上传文件与预览结果是否一致，避免浏览器旧状态、误操作或异步返回导致上一份表格明细混入当前订单。

安全效果：

- 订单 A 不会导入订单 B 的产品明细。
- Excel 解析结果必须来自当前上传文件。
- 用户仍可在当前表格基础上手动修正产品、数量、单价和详细要求，保持“人工确认为准”的业务原则。

## 十二、审计留痕与可追溯性

系统对关键业务流程保留记录，方便日后追溯责任和核查业务过程。

已具备的审计能力包括：

- 订单状态流转记录。
- 审批动作、审批人、审批时间和审批原因记录。
- 发货信息、物流单号和发货状态记录。
- 用户登录时间记录。
- 登录失败与锁定状态记录。
- 后端服务日志、Nginx 访问日志和 PM2 运行日志。

安全价值：

- 管理层可追踪订单从创建到发货的完整过程。
- 出现错单、漏单、越权操作或流程争议时，可根据记录核查。
- 系统管理员可通过服务日志排查访问异常和运行异常。

## 十三、服务器与运维安全

### 13.1 服务器运行安全

系统部署于阿里云 ECS，后端服务由 PM2 守护运行，Nginx 作为统一入口。

安全效果：

- 应用服务异常退出后可自动拉起。
- 服务日志可持续记录运行状态。
- Nginx 可统一管理访问入口和静态资源。

### 13.2 环境变量安全

数据库连接串、JWT 密钥、管理员初始化信息等敏感配置由服务器环境变量管理，不应写入公开文档或前端代码。

甲方运维要求：

- 不公开服务器 `.env` 文件。
- 不将数据库密码、服务器私钥、管理员密码发到微信群或普通文档。
- 交付后由甲方指定管理员统一保管关键账号和密码。

### 13.3 账号生命周期管理

建议甲方建立基础账号管理制度：

1. 员工入职时按岗位开通账号。
2. 员工调岗时及时调整角色权限。
3. 员工离职时立即停用账号。
4. 管理员账号不得多人共用。
5. 初始密码应在首次登录后及时修改。

## 十五、上线与运维建议

为确保系统长期稳定、安全运行，建议甲方在正式上线前后重点落实以下事项：

| 优先级 | 建议事项 | 说明 |
|---|---|---|
| 高 | 启用 HTTPS | 正式域名访问时配置 SSL 证书，保护登录凭证和业务数据传输 |
| 高 | 保管好数据库和服务器密码 | 由企业负责人或指定管理员统一保管，不在聊天工具中传播 |
| 高 | 定期检查备份 | 每 7 天确认本地备份是否生成，定期检查 SHA256 校验文件 |
| 高 | 做恢复演练 | 建议每季度至少恢复一次备份到测试库，验证备份可用 |
| 中 | 建立账号管理制度 | 入职开通、调岗调整、离职停用，避免账号长期闲置 |
| 中 | 定期检查日志 | 查看 Nginx、PM2 和后端错误日志，及时发现异常访问 |
| 中 | 限制本地备份传播 | 本地 `.dump` 文件不得随意发给非授权人员 |
| 低 | 后续第三方测试 | 如系统承载更多敏感数据，可委托安全机构做渗透测试 |

智能制造订单管理系统当前交付版本已经具备较完整的基础安全体系。系统通过登录认证、密码哈希、角色权限、后端强制授权、订单流程约束、输入校验、Excel 上传校验、数据库内网访问、RDS 云盘加密、RDS 自动备份和企业本地冷备份等措施，保障了企业订单、客户、库存、物料和审批数据的安全性、完整性和可恢复性。

从甲方生产使用角度看，系统已具备进入受控试运行和正式部署准备阶段的条件。后续安全工作的重点不再是单纯依靠系统功能本身，而是需要甲方持续落实账号管理、密码保管、备份检查、恢复演练和 HTTPS 上线等运维制度。

总体判断：**本系统当前安全设计合理，核心数据保护措施完整，运行风险可控，可作为客户企业第一阶段数字化订单管理平台投入生产试运行。**
