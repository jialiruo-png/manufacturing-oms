## 一、项目概述

**智能制造订单管理系统**（简称"YMT OMS"）是一套面向制造业中小企业的**订单全生命周期管理平台**，覆盖从客户接单、审批、采购备料、生产排程、发货物流到老板决策看板的完整业务链条。

系统采用 React 18 + Express + PostgreSQL 的现代前后端分离架构，第一阶段生产与交付架构为**阿里云 ECS + Nginx + PM2 + 阿里云 RDS PostgreSQL**。前端静态资源和后端服务部署于 ECS，数据库由阿里云 RDS 托管，ECS 与 RDS 通过同地域内网通信，支持 PC 端浏览器访问，可支撑 50+ 并发用户与 10 万级订单数据规模。

## 二、项目背景

客户企业是一家中型机电制造企业，主营产品出口与国内分销并行。在引入本系统前，企业面临以下管理瓶颈：

1. **订单录入依赖 Excel**：业务员手工填表，版本混乱、易出错，客户信息散落在 13 个员工的个人电脑里
2. **采购与生产脱节**：业务员靠微信群发通知采购，常出现"漏单 / 错单 / 规格写错"
3. **库存不透明**：缺货才发现、多采购导致呆滞
4. **审批靠截图**：老板审批通过微信群 @，无凭证、责任不清
5. **数据滞后**：月底手工汇总 Excel，经营数据滞后 30 天
6. **客户资产流失**：业务员离职带走客户名单，公司无积累

本项目即是为彻底解决上述痛点而设计，将企业全部业务流程**数字化、可视化、可追溯**。

## 四、系统用户与角色

系统采用 **RBAC（基于角色的访问控制）** 模型，共 **6 类业务角色 + 3 类经理子角色**：

### 4.1 业务员（sales）

- 新建订单、Excel 导入订单、提交审批
- 管理负责客户（建档、沟通记录、订单关联）
- 查看本人订单的全生命周期进度
- 不可越权访问他人订单

### 4.2 采购（purchasing）

- 接收已审批订单，录入物料清单
- 维护物料状态（采购中 / 已备齐）
- 管理库存台账，调整库存余量
- 物料备齐后流转至生产环节

### 4.3 生产（production）

- 接收备料完成的生产任务
- 录入生产备注
- 完成生产后流转至物流环节

### 4.4 物流（logistics）

- 接收待发货订单
- 录入快递单号、物流公司
- 提交发货审批请求

### 4.5 内勤跟单（manager / clerk）

- 审批物流提交的发货请求
- 只读浏览全部用户信息（无修改权）
- 通过 / 驳回发货

### 4.6 审批经理（manager / approval_manager）

- 审批业务员提交的订单
- 通过 / 退回修改 / 驳回订单
- 查看审批历史记录

### 4.7 系统管理员（manager / system_admin）

- 用户管理（注册审核、角色分配、启用 / 禁用、改密）
- 拥有全部业务环节的查看权限
- 系统级配置与维护

## 五、核心功能模块

> 完整功能清单见 **D3 功能清单一览表**，共 106 个功能点（100 已实现 + 6 预留扩展）。

### 5.1 订单管理

- 订单全生命周期管理：草稿 → 待审批 → 采购中 → 生产中 → 待发货 → 待发货审批 → 已发货
- 合同编号自动生成
- 订单详情侧滑抽屉，含完整工作流时间线
- 支持订单编辑、删除（草稿态）、批量筛选

### 5.2 客户管理

- 客户档案：基本信息 + 联系方式 + 地址 + 备注
- 客户详情页：3 卡片 + 时间线（基本信息 / 沟通记录 / 订单历史）
- 沟通记录全留痕，业务员离职无损交接

### 5.3 采购与物料

- 物料按订单聚合展示（自主创新点之一）
- 手动新增 / 编辑 / 删除物料
- Switch 一键切换备齐状态
- 库存台账：状态标记（正常 / 偏低）+ 实时余量

### 5.4 生产计划

- 生产任务列表（按订单维度）
- 生产备注录入
- 一键完成生产并流转

### 5.5 物流发货

- 待发货列表与已发货分离
- 快递单号录入、物流公司选择
- 发货审批留痕

### 5.6 审批工作流

- **基于状态机的多角色多级审批**（自主创新点之一）
- 11 个订单状态 + 20+ 条迁移规则
- 退回修改、驳回发货等"反向流转"完整闭环
- 每次状态变化自动落审计日志

### 5.7 仪表盘与报表

- 经营 KPI 卡片（订单数 / 销售额 / 客户数 / 待审批数）
- 月度销售趋势图（含同比环比）
- 风险预警订单（临近交期 / 已逾期红标）
- 客户地理分布图（基于 Leaflet 矢量地图）
- 角色化数据过滤：业务员只看自己的，经理看全局

### 5.8 Excel 导入

- **客户名称智能识别 + 乱码兜底方法**（自主创新点之一）
- 五层正则识别策略 + UTF-8/Latin-1 mojibake 自动检测
- 表头自动识别（35 行内扫描、中英文兼容）
- 日期、金额、装箱信息全自动解析
- 解析预览 → 前端编辑 → 确认导入

### 5.9 用户与权限

- 注册审核机制（自助注册 → 管理员审批）
- 三级权限模型：路由级 / 接口级 / 数据级
- PBKDF2-SHA512 密码加密
- JWT + tokenVersion 失效控制
- 全部敏感操作落审计日志

## 八、数据安全与备份

### 8.1 数据库存储加密

生产数据库使用阿里云 RDS PostgreSQL。RDS 可启用云盘加密能力，用于保护数据库底层磁盘、快照和云端静态数据。该加密不改变系统使用方式：企业管理员、总经理和授权用户仍可在系统内正常查看、审批、导出和恢复业务数据。

### 8.2 自动备份与冷备份

- **RDS 自动备份**：由阿里云 RDS 控制台配置，开发/试运行阶段建议保留 7 天。
- **企业经理电脑冷备份**：企业经理电脑通过本机定时任务每 7 天自动从 RDS 导出一份 PostgreSQL custom dump，保存到 `~/Desktop/Database`，同时生成 SHA256 校验文件。
- **备份文件说明**：本地 `.dump` 文件不是普通文本，不能直接阅读，但未额外加密时可用于数据库恢复。当前阶段优先保证企业负责人可掌控、可恢复；若后续多人接触备份文件，再评估独立文件加密。
