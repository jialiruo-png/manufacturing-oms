# 数据库设计文档

> 项目：客户企业制造业订单管理系统（Manufacturing OMS v5）  
> 数据库：Aliyun RDS PostgreSQL  
> ORM：Prisma Client + Prisma Migrate  
> 当前生产库：`manufacturing_oms`

## 一、数据库概述

### 1.1 数据库选型

系统采用 PostgreSQL 作为关系型数据库，第一阶段生产环境使用阿里云 RDS PostgreSQL。后端通过 Prisma ORM 访问数据库，数据库结构以 `backend/prisma/schema.prisma` 和 `backend/prisma/migrations/` 下的迁移文件为准。

当前生产访问方式：

| 项目 | 说明 |
|---|---|
| 数据库服务 | 阿里云 RDS PostgreSQL |
| 实例 ID | `<RDS 实例 ID>` |
| 数据库名 | `manufacturing_oms` |
| 连接方式 | ECS 通过阿里云内网地址连接 RDS |
| 应用账号 | 仅访问本项目数据库，不使用超级管理员账号作为应用账号 |
| 迁移工具 | Prisma Migrate，生产执行 `prisma migrate deploy` |

生产环境连接变量：

```bash
DATABASE_URL
DATABASE_URL_UNPOOLED
```

两者均不得提交到代码仓库。

### 1.2 命名规范

- 表名使用 Prisma model 名称，对应 PostgreSQL 双引号表名，如 `"User"`、`"Order"`。
- 主键统一使用 `id Int @id @default(autoincrement())`。
- 外键字段使用 `<业务对象>Id`，如 `customerId`、`orderId`、`salespersonId`。
- 时间字段统一使用 `createdAt`、`updatedAt`、业务时间字段使用明确名称，如 `deliveryDate`、`orderDate`。
- 状态字段使用英文短码保存，前端和后端负责转为中文展示。

### 1.3 字段类型约定

| Prisma 类型 | PostgreSQL 含义 | 使用场景 |
|---|---|---|
| `Int` | integer | 主键、数量、进度百分比 |
| `String` | text | 名称、状态、备注、编号 |
| `Float` | double precision | 金额、单价、库存数量、体积重量 |
| `Boolean` | boolean | 权限位、加急标记、确认标记 |
| `DateTime` | timestamp | 创建时间、更新时间、交期、登录时间 |

金额字段当前使用 `Float`，满足当前轻量级订单管理需求。若后续进入财务结算或对账系统，建议迁移为 PostgreSQL `numeric/decimal`。

## 二、ER 图

```text
User
 |--< Customer.salespersonId
 |--< Order.salespersonId
 |--< PasswordResetRequest.userId

Customer
 |--< Order.customerId
 |--< CommLog.customerId

Product
 |--< BomItem.productId
 |--< Order.productId
 |--< OrderItem.productId

Order
 |--< OrderItem.orderId
 |--< Material.orderId
 |--< ApprovalLog.orderId

OrderItem
 |--< Material.orderItemId

Inventory
  独立库存台账，不直接绑定订单；通过物料名称、规格、单位进行业务匹配。
```

说明：

- 订单主表 `Order` 保存订单汇总和流程状态。
- 订单明细 `OrderItem` 保存每个产品行、详细要求、包装物流字段。
- 采购物料 `Material` 由采购手动维护，可关联到具体 `OrderItem`。
- 通知数据不单独建表，后端 `notifications` 路由基于订单、物料、用户审核和密码重置申请实时计算。

## 五、索引设计

### 5.1 主键与唯一索引

| 索引 | 表 | 字段 | 用途 |
|---|---|---|---|
| 主键索引 | 全部业务表 | `id` | 单表记录唯一标识 |
| `Product_code_key` | Product | `code` | 产品编号唯一 |
| `User_phone_active_key` | User | `phone WHERE deletedAt IS NULL` | 活跃用户手机号唯一 |
| `Order_contractNo_nonempty_key` | Order | `contractNo WHERE contractNo <> ''` | 非空合同号唯一 |

### 5.2 业务查询索引

| 表 | 索引 | 支撑场景 |
|---|---|---|
| User | `status, deletedAt` | 用户审核、启用/禁用列表 |
| User | `role, status, deletedAt` | 按角色查启用用户 |
| User | `managerSubRole, status, deletedAt` | 经理层权限筛选 |
| Customer | `salespersonId` | 按业务员筛客户 |
| CommLog | `customerId, createdAt` | 客户详情沟通记录 |
| Order | `status, deliveryDate, createdAt` | 各模块按状态和交期查订单 |
| Order | `customerId, createdAt` | 客户订单历史 |
| Order | `salespersonId, status, createdAt` | 业务员数据隔离和列表 |
| Material | `orderId, status` | 订单详情物料状态 |
| Material | `status, urgent` | 采购缺料和加急提醒 |
| ApprovalLog | `orderId, createdAt` | 订单审批时间线 |

### 5.3 复合索引策略

系统的主要查询不是全库全文检索，而是围绕“角色模块 + 状态 + 时间”的列表查询：

- 业务员侧按 `salespersonId/status/createdAt` 查询自己的订单。
- 采购侧按 `status=procurement` 查询待备料订单。
- 生产侧按 `status=production` 查询生产订单。
- 物流侧按 `status=ready_ship/pending_ship_approval/shipped` 查询发货链路。
- 总经理/内勤侧按 `pending_approval` 和 `pending_ship_approval` 查询待审批订单。

因此索引优先服务状态流转列表、业务员数据隔离、客户历史和审批日志。

## 七、数据迁移策略

### 7.1 Prisma Migrate 工作流

数据库结构变更必须通过 Prisma migration 管理：

```bash
cd backend
npm run db:migrate
```

迁移文件生成后应提交到：

```text
backend/prisma/migrations/
```

生产环境只执行：

```bash
npm --prefix backend run db:deploy
```

禁止在生产库直接使用 `db push`，避免跳过迁移历史和审计记录。

### 7.2 生产环境迁移规范

生产数据库迁移前应遵循：

1. 确认当前连接的是阿里云 RDS `manufacturing_oms`，不是本地或测试库。
2. 先创建 RDS 自动备份点，必要时手动执行本地冷备份。
3. 在测试环境或本地开发库跑过迁移。
4. 执行 `prisma migrate deploy`。
5. 重启后端 PM2 服务并检查 `/api/health`。
6. 抽查用户登录、订单列表、订单创建、审批、采购、生产、发货等关键链路。

## 八、数据安全、备份与归档

### 8.1 数据库存储加密

生产库使用阿里云 RDS PostgreSQL，可开启云盘加密保护底层磁盘、快照和云端静态数据。该能力对应用透明：

- 不影响 Prisma 查询。
- 不影响管理员和授权用户在系统内查看业务数据。
- 不会自动加密本地 `pg_dump` 导出的 `.dump` 文件。

### 8.2 备份策略

当前采用双层备份：

| 层级 | 方式 | 说明 |
|---|---|---|
| 云端备份 | RDS 自动备份 | 由阿里云 RDS 控制台配置，用于云端恢复和回滚 |
| 本地冷备份 | 企业经理电脑定时备份 | 每 7 天通过 ECS 执行 `pg_dump`，保存到 `~/Desktop/Database` |

本地备份格式：

- PostgreSQL custom dump：`.dump`
- 校验文件：`.sha256`
- 日志文件：`backup.log`

本地 `.dump` 文件不是普通文本，不能直接阅读，但可以通过 `pg_restore` 恢复。当前阶段默认不额外加密，优先保证企业负责人可掌握、可恢复；如后续多人接触备份文件或进入更高合规阶段，再启用独立文件加密。

### 8.3 归档建议

当前系统数据量处于轻量阶段，暂不拆分归档表。后续当订单数据达到数十万级以上时，可评估：

- 按年份归档已发货订单。
- 将历史审批日志转入归档表。
- 对客户沟通记录按时间分区或归档。
- 将附件、图片等大文件迁移到对象存储，数据库只保存元数据。

## 九、设计结论

当前数据库设计围绕制造业订单流转展开，核心链路为“客户 -> 订单 -> 订单明细 -> 采购物料 -> 生产/发货 -> 审批日志”。用户权限、业务归属、登录安全、密码重置和库存台账已形成完整闭环。

第一阶段生产环境已使用阿里云 RDS PostgreSQL，配合 Prisma Migrate 管理结构变更，使用 RDS 云盘加密、RDS 自动备份和企业经理电脑 7 天冷备份保障数据安全与恢复能力。该设计可支撑当前小型制造企业内部订单、采购、生产、物流和经理审批的真实业务运行。
